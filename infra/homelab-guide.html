Topology & network map

One physical box at home (OptiPlex 7090) running Proxmox VE. Everything else is a guest. Public site is unrelated: it's Hugo on Cloudflare Pages.

LAN 192.168.0.0/24 Tailnet (CGNAT 100.x) NFS v4.1 from NAS Public

The shape of it:

  • Public surface is just Cloudflare Pages serving the Hugo site. Everything else is on the tailnet — no exposed home ports.
  • Wildcard *.monotrope.au is a CNAME to the Proxmox host's Tailscale IP (100.88.127.39). Devices on the tailnet resolve and reach services through Caddy on PVE.
  • Caddy on PVE terminates TLS (Let's Encrypt via Cloudflare DNS-01 for the wildcard) and reverse-proxies by hostname to the right LXC's port.
  • NAS (Synology, 192.168.0.49) holds the bulky data — books, audiobooks, media — and serves it over NFS. LXCs mount what they need.
  • NFS identity: NAS user homelab = uid/gid 1028. Every container that touches NFS runs as 1028, otherwise root squashes to nobody and reads fail.

Network details

LAN

  • Single flat 192.168.0.0/24. Router at .1, NAS at .49, PVE at .59, guests at .96–.99 and .86 (HAOS).
  • All PVE guests use DHCP with MAC reservations at the router — never static-in-guest. LXCs use SLAAC for IPv6 (ip6=auto, never dhcp).
  • PVE bridge vmbr0 bridges the host NIC; guests attach directly. No internal Proxmox subnets.

Tailnet

  • Only the PVE host runs Tailscale. Guests reach the tailnet only through PVE (and they don't need to — services bind LAN).
  • *.monotrope.au is a wildcard CNAME pointing to PVE's tailscale IP. So abs.monotrope.au resolves only on tailnet-connected devices.
  • Caddy binds both the LAN IP (192.168.0.59) and the Tailscale IP (100.88.127.39) — reachable from either side.
  • Inspect: tailscale status, tailscale ip -4, tailscale ping <peer>.

Docker networks (per LXC)

Compose creates one bridge network per project, named <dir>_default. So:

  • apps LXC: audiobookshelf_default, calibre_default, miniflux_default (app+db share this one), koinsight_default, audible-ingest_default — no shared net, each project isolated.
  • media-stack: single media-stack_default; qbittorrent doesn't use it — it joins gluetun's network namespace via network_mode: service:gluetun. That's how qbit's traffic is forced through the VPN. Inbound to qbit's WebUI hits gluetun's published port 8080.
  • Inspect: docker network ls, docker network inspect <name>.

State & persistence

Three layers of state. Treat them differently.

LayerWhatWhereReproducible?
Code/config Compose files, systemd units, Caddyfile, all settings This repo (infra/ansible/) — applied via make home Yes — Ansible is the source of truth. Edit here, never on the host.
Runtime state Per-service databases, caches, queues Docker named volumes on each LXC; native services on host filesystems Mostly. Recreatable but losing it = losing sessions, scan results, progress, listening position.
Auth tokens / cred state Audible OAuth, Kobo OAuth, Hermes Telegram/email creds, GWS tokens Volumes (audible_config, kobodl_config) & /root/.hermes/ No — interactively bootstrapped, irreplaceable without re-doing OAuth flows. File-level backup before any migration.
Bulk data Audiobooks, books, media NAS volumes — Synology snapshots + its own backup discipline NAS handles it. Don't keep authoritative copies on LXC disks.

Common recipes

Force a re-ingest of one audiobook (Audible pushed an update)

Same ASIN, new file. The sweep skips folders that already have a .m4b, so the gate is the file, not the state.

# 1. Drop the old file
ssh root@192.168.0.97 \
  docker exec audible-ingest-audible-ingest-1 \
    rm "/audiobooks/<Author>/<Title>/<file>.m4b"

# 2. (Optional) clear the ASIN from state.json so it reports as a fresh download
ssh root@192.168.0.97 docker exec audible-ingest-audible-ingest-1 python3 -c '
import json, pathlib
p = pathlib.Path("/var/lib/audible-ingest/state.json")
s = json.loads(p.read_text())
s.pop("<ASIN>", None)
p.with_suffix(".tmp").write_text(json.dumps(s, indent=2, sort_keys=True))
p.with_suffix(".tmp").replace(p)
'

# 3. Trigger the sweep (one book, no throttle)
ssh root@192.168.0.97 \
  docker exec -e MAX_PER_RUN=1 -e SLEEP_MIN=0 -e SLEEP_MAX=0 \
    audible-ingest-audible-ingest-1 /usr/local/bin/audible-ingest

# 4. Force ABS to rescan (NFS-mounted libraries don't always fire watcher events)
LIB=$(ssh root@192.168.0.97 docker run --rm -v audiobookshelf_config:/c:ro alpine sh -c \
  'apk add -q sqlite >/dev/null && sqlite3 /c/absdatabase.sqlite "SELECT id FROM libraries;"')
TOK=$(ssh root@192.168.0.97 docker run --rm -v audiobookshelf_config:/c:ro alpine sh -c \
  'apk add -q sqlite >/dev/null && sqlite3 /c/absdatabase.sqlite "SELECT token FROM users WHERE type=\"root\";"')
ssh root@192.168.0.97 \
  curl -sS -X POST -H "Authorization: Bearer $TOK" \
    "http://127.0.0.1:13378/audiobookshelf/api/libraries/$LIB/scan?force=1"

Troubleshooting cheatsheet

An import doesn't show up in ABS
  • Confirm the file is on the NAS path the container sees: docker exec audiobookshelf-audiobookshelf-1 ls "/audiobooks/<Author>/<Title>"
  • NFS watchers are unreliable. Trigger a forced scan via the API (see recipe).
  • ABS dedupes by libraryItemId, not file hash. Same path = same item — if you replace a file in place, scan shows Updated, not Added.
audible-ingest is downloading the wrong title / failing
  • Audible "Sable 404" errors are upstream — Audible has removed the title from your library or it's region-blocked. Pin the ASIN: edit state.json set "status": "pinned".
  • Check the current view: docker exec audible-ingest-audible-ingest-1 audible library list | grep -i <title>.
  • Tokens expired: audible library list returns an auth error → re-run quickstart.
qbit/sonarr can't reach the internet
  • qbit runs inside gluetun's netns. If gluetun is unhealthy, qbit has no network at all.
  • docker logs gluetun | tail -50 — look for handshake / PMP errors.
  • Forwarded port pushed to qbit via /scripts/qbit-port.sh on each tunnel-up. If the port stops working, restart gluetun (which restarts qbit by dependency).
NFS reads fail / Permission denied on /library or /data
  • Running as root inside an unprivileged LXC? You'll squash to nobody on the NAS. Run as uid 1028 (every compose file is already set up that way; the trap is when running ad-hoc docker run …).
  • Check the mount is up: mount | grep nfs on the LXC.
  • NAS-side: NFS export permissions for the LXC's IP and the homelab user.
Caddy serves "no service mapped for <host>" 404
  • You added a new subdomain to DNS but not to /etc/caddy/Caddyfile. Add a @name host … + handle block (mirror an existing one), then systemctl reload caddy.
  • Or the DNS record points somewhere other than the tailscale IP — check dig.
Need a one-off shell on a host without SSH config
  • From any machine on the tailnet: ssh root@192.168.0.59 reaches PVE.
  • From PVE: pct enter <vmid> for an LXC, qm terminal 100 for HAOS.
